  - ✅ Rate limiting (5 login attempts per 15 minutes per email)

#### `POST /api/auth/refresh`

- Input: `refresh_token` cookie + `X-CSRF-Token` header (if applicable)
- Output: New JWT + rotated refresh token
- Side Effects:
  - Old refresh token marked as revoked
  - New access_token cookie issued
  - New refresh_token cookie issued
  - New csrf_token cookie issued

#### `POST /api/auth/logout`

- Input: Authenticated user context
- Side Effects:
  - Current refresh token revoked
  - All auth cookies cleared with Set-Cookie deletion headers
  - User cannot use old refresh token

### 4. CSRF Protection (COMPLETE)

Located in [Backend/src/Program.cs](Backend/src/Program.cs):

**Double-Submit Pattern**:

- Server issues readable `csrf_token` cookie
- JavaScript reads cookie and includes value in `X-CSRF-Token` header
- Middleware validates: cookie value == header value
- Exempted endpoints: `POST /api/auth/login|register|verify-email` (for initial token issuance)
- Applied to all unsafe methods: POST, PUT, DELETE, PATCH

**Middleware Implementation**:

```csharp
// Exempted endpoints - no CSRF check needed
if ((request.Method == "GET" || request.Method == "HEAD" || request.Method == "OPTIONS")
    || IsExemptedEndpoint(request.Path))
{
    await next();
    return;
}

// Validate CSRF for unsafe methods
var csrfToken = request.Cookies["csrf_token"];
var headerToken = request.Headers["X-CSRF-Token"].FirstOrDefault();

if (csrfToken != headerToken)
{
    context.Response.StatusCode = 403;
    return;
}
```

### Protected Requests

```javascript
// Get CSRF token from cookie for subsequent requests
const csrfToken = document.cookie
  .split("; ")
  .find((row) => row.startsWith("csrf_token="))
  ?.split("=")[1];

// Include CSRF token in header for POST/PUT/DELETE
const response = await fetch("/api/protected", {
  method: "POST",
  credentials: "include",
  headers: {
    "X-CSRF-Token": csrfToken,
    "Content-Type": "application/json",
  },
  body: JSON.stringify(data),
});
```

## 🔧 Troubleshooting

### "Invalid Signature" Errors

- **Cause**: `Jwt:Key` mismatch between login and API
- **Solution**: Ensure same key in appsettings across all services

### "Audience Validation Failed"

- **Cause**: Token audience doesn't match validation parameters
- **Solution**: Verify `Jwt:Audience` matches `ValidAudience` in middleware

### CSRF Token Validation Failed

- **Cause**: Missing `X-CSRF-Token` header or token mismatch
- **Solution**: Ensure header includes cookie value for non-GET requests

### Cookies Not Secure

- **Cause**: HTTP instead of HTTPS
- **Solution**: Enable HTTPS in production (`Secure` flag requires HTTPS)

### Clock Skew Rejection

- **Cause**: Server/client time difference > 30 seconds
- **Solution**: Synchronize system clocks or adjust `ClockSkew` in middleware
